# Правила для агентов в этом репозитории

- Изменение - по одной задаче Jira; в описании PR - ключ задачи.
- Правила предметной области R1-R6 из [README.md](README.md) не нарушать; спорное изменение
  правила - только через решение человека (ADR в docs/adr/).
- Настройки CI (`.github/`) и фабрики (`.factory/`) агент не меняет: страж фабрики такое
  изменение не публикует.
- Секреты, токены и пароли в репозиторий не попадают.
- Язык описаний и комментариев - русский; имена в коде - английские.
- Перед сдачей изменения проходят `npm run lint`, `npm run format:check`, `npm run typecheck`
  и `npm test` (`npm run format` форматирует). Правила R1-R6 и выбор победителей - чистые
  функции в `api/src/domain`: без NestJS и базы (ADR-3).
- Новое правило предметной области - с модульным тестом в `api/test` и, если его видно
  пользователю, со сквозной проверкой в `e2e/tests`.

## Спецификации - OpenSpec

- Изменение поведения начинается с изменения OpenSpec в
  `openspec/changes/<ключ задачи в нижнем регистре>-<имя>/` (например
  `draw-12-redraw-unclaimed-prize`) по схеме `factory` из `openspec/config.yaml`: замысел,
  требования со сценариями, архитектурные решения (ADR), задачи, план проверки.
  `npm run spec:validate` проходит без ошибок.
- Изменение пишет человек со своим экзокортексом: навыки OpenSpec - `.claude/skills` (Claude
  Code, команды `/opsx:*`) и `.agents/skills` (Codex). Утверждает владелец слиянием PR; затем
  метка `agent` на задачу - фабрика отдаёт изменение агенту.
- Агент-разработчик `openspec/` не меняет: пишет тесты по сценариям требований до кода, потом
  код. Когда задачи изменения сделаны, человек архивирует его (`openspec archive`) PR-ом -
  требования переходят в живые спецификации `openspec/specs/`.
