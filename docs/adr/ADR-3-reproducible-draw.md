# ADR-3. Результат розыгрыша воспроизводим из зерна

Статус: принято, 15.10.2026.

Проблема: участник должен убедиться, что организатор не подобрал победителей (R4).

Решение:
- зерно - 32 случайных байта при создании розыгрыша; его хэш SHA-256 публикуется сразу, само зерно - после выбора победителей;
- победителей выбирают только после конца приёма заявок;
- способ выбора: участники без повторов по возрастанию (как `Array.prototype.sort`), затем на шаге i - индекс из первых 8 байт HMAC-SHA256(зерно, "pick:i") по модулю числа оставшихся; выбранный выходит из списка (R5);
- после выбора API отдаёт зерно и список участников, веб-приложение пересчитывает итог в браузере.

Последствия: любой с зерном и списком участников получит тех же победителей; код выбора - чистая функция `api/src/domain/rules.ts` (правило `domain-is-pure` в `.dependency-cruiser.cjs`). Повторный выбор с другим зерном этому решению противоречит; повтор невостребованного приза - в уточнении ниже.

## Уточнение: повтор невостребованного приза (DRAW-48)

Статус: принято.

Проблема: победитель не подтвердил приз за 3 дня (R6), приз нужно разыграть снова, сохранив проверяемость выбора (R4) и правило одного приза (R5).

Решение: повтор не берёт новое зерно. "Заново среди всех участников" значит: среди всех участников розыгрыша, кроме уже выбранных победителей, следующим шагом той же последовательности - индекс из HMAC-SHA256(зерно, "pick:i") по модулю числа оставшихся, где i - число уже сделанных выборов. Не подтвердивший приз победитель из кандидатов уже вышел.

Последствия: повтор воспроизводим из опубликованного зерна так же, как исходный выбор; веб-приложение пересчитывает и его. Других источников случайности в `api/src/` нет: правило-страж `no-random-outside-seed` в `.factory/config.yml`.
